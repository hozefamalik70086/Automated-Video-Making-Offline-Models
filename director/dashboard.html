Story & LLM how the film is written

Story parameters

Genre, length and where the script comes from.

Want a 30 or 60 s video? Set the TOTAL length here and the pipeline divides it across your scenes automatically (e.g. 60 s ÷ 2 scenes = 30 s each). Every scene is then rendered as small 1-second chunks that are joined right after creation, so long videos render without running the GPU out of memory.
If the custom story file contains scene text (not just comments), it is used instead of the LLM. Leaving it as an all-comment template makes the text model write the story.

Text model (LLM)

Backend + model used to write the story.

Video output

Final video resolution and frame rate. Default is 1080×1920 (9:16 vertical — Reels / TikTok / Shorts).

Chunked rendering (1s segments)
render each scene as N×1s clips and join them after creation — avoids OOM / hangs at high FPS & resolution
Chain frames between segments
start each segment from the previous segment's last frame for continuous motion
The pipeline uses the SMALLER of "Segment length" and "Max segment length", so a long video can never submit one huge generation — that was the cause of ComfyUI stopping / "not enough memory". At 1080×1920 keep 1s; raise Max only if you lower resolution or have VRAM to spare.

Keyframe image

Text-to-image (still) that starts each video.

Motion prompt boost

Optional text appended to every video prompt. WARNING: it must agree with the prompt wording — appending "dynamic motion" to a "slow/gentle" prompt makes output static (verified in testing). Prefer fixing prompts at the source (LLM/fallback).

Camera move

Forces a cinematic camera instruction to be prepended to every video prompt (overrides whatever the story suggested). "auto" keeps the story's own camera; "none" adds nothing.

LTX-2.3 two-pass quality knobs

Advanced: base pass (strength 0.7, 8-step sigmas) then refine pass (strength 1.0, 3-step sigmas). These map to the workflow nodes and are applied automatically.

Audio / narration

Post-processor (runs after the film is stitched). Synthesizes speech from each scene's Dialogue (ambient "audio" lines are sound cues and are never spoken), muxes it into the video, and optionally burns subtitles. Requires the optional edge-tts package; failures never break the base pipeline.

Characters (identity locking)

Phases 0–4: the director extracts the cast from the story, writes a descriptor lock per character, renders a locked reference image, and injects a consistency anchor into every image/video prompt so faces stay identical across scenes. Settings map to the characters block of config.json.

Enable character locking
extract + lock the cast in every run
Auto-generate reference images
render each lock in ComfyUI on first use
Runs python characters.py --setup with the current config — extracts the cast from the story, writes descriptor locks (via Ollama or a built-in fallback) and renders reference images in ComfyUI. Output appears in a popup. Turn auto-generate reference images off to use text-only locks.
Custom Story Editor optional manual script

Format: blocks separated by a line of three or more dashes ---. Each block can have Image: ... and Video: ... lines (motion-focused!). Lines starting with # are comments.

The active story source is set in the Story & LLM tab via story.custom_story_file. The default custom_story.txt is all comments so the LLM writes the story. Filling it here with real scenes bypasses the LLM.
